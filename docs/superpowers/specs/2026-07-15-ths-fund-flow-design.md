# 同花顺资金净流入接入设计

## 目标

为自定义板块看板提供免费、可每日更新的个股资金净流入数据，解决现有东方财富逐股历史资金流日期滞后、最新值为空且前端误显示为 0 的问题。

本功能采用同花顺公开资金流页面经 AKShare 适配的全市场即时接口。页面统一使用“资金净流入（同花顺口径）”，不得称为“主力净流入”或“量化资金流”。

## 数据源

- 接口：`ak.stock_fund_flow_individual(symbol="即时")`
- 更新方式：收盘完整日更时调用一次
- 返回范围：全市场股票；本机验证返回约 5,198 条
- 使用字段：股票代码、股票简称、最新价、涨跌幅、换手率、流入资金、流出资金、净额、成交额
- 金额单位：将“亿”“万”和普通数字统一解析为元

该接口不提供大单和特大单拆分，因此只保存总资金净额，不生成超大单、大单、中单、小单字段。

## 数据流程

1. 收盘日更调用一次全市场接口。
2. 校验返回行数、股票代码唯一性和金额可解析率。
3. 将全量结果保存为按交易日分区的原始快照。
4. 按六位股票代码匹配自定义板块成员。
5. 把匹配到的个股资金净额写入对应交易日的股票行。
6. 板块当日资金净流入等于当日有效成分股资金净额之和。
7. 同时写入数据来源、资金日期、有效股票数和总股票数。

建议快照路径：

```text
data/custom_fund_flow_ths/YYYYMMDD/all.json
```

## 输出字段

个股行增加或复用：

```json
{
  "fundFlowDate": "2026-07-15",
  "fundFlowSource": "ths_stock_fund_flow_individual",
  "mainNetInflow": 12345678.0
}
```

为兼容现有页面，金额暂写入现有 `mainNetInflow` 字段，但所有页面文案改为“资金净流入（同花顺口径）”。后续如需同时接入真正的大单资金，再迁移到独立的 `netFundInflow` 字段。

板块日行保留：

```json
{
  "mainNetInflow": 123456789.0,
  "fundFlowStockCount": 18,
  "fundFlowLatestDate": "2026-07-15",
  "fundFlowSource": "ths_stock_fund_flow_individual"
}
```

## 新鲜度与失败处理

- 只有资金日期与行情日期相同的数据才能计入当日板块合计。
- 缺失值保持 `null`，不得转换为 0。
- 页面必须展示覆盖数，例如“覆盖 18/21”。
- 当日接口失败时，保留已有快照并输出 warning；不得把前一交易日金额写入当天。
- 当日覆盖率低于 80% 时，板块总额仍可展示，但必须标记“覆盖不足”；方向强度计算不得使用该资金项。
- 同一交易日已经存在通过校验的全量快照时，普通日更直接复用；显式刷新参数才重新请求。

## 页面调整

- “主力净流入”统一改为“资金净流入”。
- 辅助说明显示“同花顺口径、资金日期、覆盖数”。
- 正值使用上涨色，负值使用下跌色，缺失显示“暂无”。
- 方向强度页面后续只能在资金覆盖率达到 80% 时使用资金维度。

## 验证

自动测试覆盖：

1. 中文金额单位转换为元。
2. 全市场数据按六位代码正确匹配。
3. 同日数据写入，跨日数据拒绝写入。
4. 个股缺失值保持 `null`。
5. 板块合计只统计有效值并输出正确覆盖数。
6. 有效快照被复用，失败请求不会覆盖已有数据。
7. 页面不再出现“主力净流入”误导文案。

人工验收：

- 随机抽查至少 5 只股票，与同花顺资金流页面核对净额方向和数量级。
- 检查至少 3 个板块的成分股合计与页面板块金额一致。
- 收盘完整日更完成后运行 `scripts/validate_web_data.py`。

## 不在本次范围内

- 不识别量化交易资金。
- 不提供大单、超大单拆分。
- 不补造接入日期以前的逐日历史。
- 不把资金净流入单独用作买卖信号。
